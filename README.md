# 🛡️ Splunk Alert Evidence Capture & SQL Logging Pipeline

> An automated SecOps pipeline that receives Splunk security webhooks, automatically captures headless browser screenshots of flagged URLs for forensic evidence, and logs structured metadata directly into an SQL database.

---

## 📌 Features

- **⚡ Real-Time Ingestion:** Listens for incoming Splunk alerts via custom Webhook endpoints.
- **📸 Forensic Evidence Capture:** Uses Playwright to automatically take a screenshot of malicious/suspicious URLs upon alert arrival.
- **⏱️ Precise Timestamps:** Tracks exact arrival times down to the second.
- **🗄️ Structured Logging:** Categorizes severity (`High`, `Medium`, `Low`) and stores metadata in PostgreSQL with optimized database indexes.

---

## 📐 Architecture Flow

[ Splunk SIEM ]
       │
       │  (HTTP POST Webhook)
       ▼
[ Flask REST API ]
       │
       ├────► 📸 Playwright (Captures URL Screenshot)
       │
       └────► 🗄️ PostgreSQL (Stores Metadata & Evidence Path)

2️⃣ Set Up Virtual Environment & Dependencies
Bash
# Create virtual environment
python3 -m venv venv

# Activate virtual environment
# On Linux/Mac:
source venv/bin/activate
# On Windows:
# venv\Scripts\activate

# Install required Python packages
pip install flask playwright psycopg2-binary

# Install Playwright browser dependencies
playwright install chromium
3️⃣ Set Up PostgreSQL Database
Update the DB_CONFIG dictionary in app.py with your database credentials:

# Python
DB_CONFIG = {
    "dbname": "your_database_name",
    "user": "your_postgres_user",
    "password": "your_postgres_password",
    "host": "localhost",
    "port": 5432,
}
Execute the schema.sql script to create the table and indexes:

 # Bash
     psql -U your_postgres_user -d your_database_name -f schema.sql
4️⃣ Start the API Server
Run the Flask application locally:

 # Bash
    python app.py
The API will listen on http://localhost:5000/splunk-webhook.

🧪 Testing Locally (Without Splunk)
You don't need a live Splunk instance to test the workflow. You can trigger a simulated alert using cURL and the provided sample_payload.json.

In a new terminal window, execute:

 # Bash
    curl -X POST [http://127.0.0.1:5000/splunk-webhook](http://127.0.0.1:5000/splunk-webhook) \
     -H "Content-Type: application/json" \
     -d @sample_payload.json
Expected Output:
 # Terminal: 
You will see logs indicating the alert was received, a screenshot was taken, and data was written to PostgreSQL.

FileSystem: A screenshot image will be generated inside static/screenshots/.

Database: A new entry will appear in the alert_logs table.

To view your logged alerts in SQL:

# SQL
    SELECT * FROM alert_logs;
🔗 Connecting to Splunk
To wire this up to a live Splunk server:

Expose your local server using ngrok (for local testing):

 # Bash
    ngrok http 5000
Copy the forwarding URL generated by ngrok (e.g., https://xyz123.ngrok-free.app).

 # In Splunk Web:

Navigate to Search & Reporting and create/open an Alert rule.

Click Trigger Actions ➔ Add Actions ➔ Webhook.

Set the URL to: https://xyz123.ngrok-free.app/splunk-webhook.

Save the alert.
